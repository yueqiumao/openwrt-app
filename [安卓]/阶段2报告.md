## 完成内容

终端 tab 从占位页换成可用页面，数据只用真机验证通过的 `/ubus` 直连。

**列表**
- 顶部搜索：名称 / IP / MAC，边输边过滤
- 筛选：全部 / 在线 / WiFi / 有线（与网页版同一套语义）
- 汇总头：`共 N 台 · 在线 N`，右侧 `有线 N · WiFi N`
- 每行：头像（按 MAC 哈希取 6 组渐变色，同一设备颜色稳定）、显示名（主机名 → IP → MAC 回退）、类型标签（频段 / 有线 / 离线 / 共享）、副行 `IP · 5G · -58 dBm` 或 `有线 · LAN2`、右侧实时上下行与在线状态

**详情弹窗**
- 名称、MAC、IPv4、IPv6（多条时显示 `首条 等 N 个`）
- WiFi：SSID、信道、信号（dBm + 百分比）、协商速率（kbps→Mbps）、连接时长
- 有线：端口、网桥、同端口共享提示
- 累计收发、实时速率、租约剩余、数据来源（无线关联表 / 网桥 FDB / DHCP 租约 / ARP 主机表）
- 空值一律 `—`

## 数据口径（对齐 collector.js devices()）

1. **只有 iwinfo 关联表里的设备算无线在线**；端口映射里 port 为 `phy\d-ap\d` 的一律剔除。
2. **只有非无线端口上的设备算有线在线**；同一 MAC 同时在无线关联表时以 WiFi 为准。
3. 租约与 `getHostHints` **只补名字/IP/IPv6，不改变在线状态**，也不会把设备单独标成在线。
4. WAN 侧邻居与路由器自身 MAC/IP 被排除（用 LAN 网段 CIDR 判定）。
5. 离线设备保留最近一次类型 30 分钟，避免刚断开就显示"未知"。
6. 排序：有线 → 5G WiFi → 2.4G WiFi → 其它 WiFi → 离线，同组按信号强度降序。
7. 有线设备的实时速率取所在端口的速率，同端口多设备标 `共享`。
8. 客户端速率按"客户端视角"差分：下行 = 路由器 tx 增量，上行 = rx 增量，dt ≤ 0.2s 不出值。
9. 缓存：租约 30s、hostHints 25s、端口映射 5s、无线 12s；关联表每 tick 重读（为了速率差分）。

## 验证

- `:app:testDebugUnitTest` **44 项全绿**（新增 7 项终端合并测试，全部喂真实 fixtures）
- 关键断言：真机 vantage 的 10 条 hosts 中 8 条是 WiFi（`phy1-ap0` 7 + `phy0-ap0` 1），只有 `lan2`/`lan3` 算有线 → `wired=2`、`wifi=8`、`online=10`；排序首条为有线；离线设备 60 秒后仍保留 `WIFI` 类型但不计入在线数；端口速率映射与共享标记
- APK 11 MB，debug 证书与阶段 1 相同，可直接覆盖安装

## 未验证项（需要真机看）

1. 头像渐变与首字母在中文主机名上的观感（规则已按 format.js，但中文字形宽度没测）。
2. 搜索框是自绘 BasicTextField，暗色主题下的光标与选中样式未在真机核对。
3. 详情弹窗高度：IPv6 多条 + WiFi 字段全满时可能接近全屏，小屏需要滚动（当前未加滚动）。
4. 无线客户端速率：空闲时可能长期显示 0 B/s（关联表计数不变），属正常。
5. 离线设备的 30 分钟记忆只在单测里验证，真机上拔网/断电后未观察。
