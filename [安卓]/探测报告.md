## 放行（status 0）

| 对象 · 方法 | 用途 |
|---|---|
| `system board` / `system info` | 固件、目标平台、hostname、uptime、load、memory |
| `network.interface dump` | 接口、IPv4/IPv6、PD、网关、DNS、累计收发 |
| `luci-rpc getNetworkDevices` | 网口 carrier/speed/duplex + 每口 stats（App 的网口卡与速率来源） |
| `luci-rpc getWirelessDevices` | 双频射频、SSID、信道、加密，并且**内嵌每接口的 iwinfo** |
| `luci-rpc getDHCPLeases` / `getHostHints` | 租约、MAC→主机名映射（阶段 2 终端页） |
| `iwinfo info <ifname>` / `iwinfo assoclist <ifname>` | SSID/信道校正、WiFi 客户端信号与收发字节 |
| `luci getTempInfo` / `getCPUInfo` | 温度文本、CPU 型号与核心数 |
| `file read`（仅 `nf_conntrack_count` / `nf_conntrack_max`） | 连接数与上限 |
| `luci.vantage wired` | 有线端口映射（含 WiFi 客户端混入，需要过滤） |

## 拒绝

| 调用 | 结果 | 影响 |
|---|---|---|
| `/cgi-bin/luci/admin/ubus`（LuCI RPC，带 ubus sid） | HTTP 200 + `Access denied`（code 5） | App 已不使用该通道 |
| `network.wireless status` | `Access denied` | 无线兜底路径不可用，只能用 `luci-rpc getWirelessDevices` + `iwinfo` |
| `file read /proc/net/dev` | code 6 | 无法用 `/proc/net/dev` 兜底网口速率 |
| `file read /sys/class/net/wan/carrier`、`speed` | code 6 | 无法用 sysfs 兜底链路状态 |
| `file read /sys/class/thermal/...` | code 6 | 温度没有 thermal_zone 兜底，只能靠 `getTempInfo` |

结论：这台路由器的 rpcd 只放行了固定白名单，`file` 对象仅 conntrack 两个路径可读。App 当前主路径（luci-rpc + iwinfo + luci + conntrack + vantage）全部命中，兜底路径基本无效但也不会被触发，属于可接受的冗余。

## 从真实返回里确认的细节

1. `getTempInfo` 文本是逗号分隔：`CPU: 48.9°C, WiFi: 53.0°C 59.0°C`（不是网页文档里的 `/`），温度解析已适配。
2. `getCPUInfo` 为 `ARMv8 Processor rev 4 (v8l) x 4 (1018MHz)`，核心数 4。
3. `getNetworkDevices` 每块网口带 `link{speed,duplex,carrier,changes}` 与完整 `stats`；`carrier` 是布尔。
4. 无线接口名是 `phy0-ap0`（5G，信道 44）、`phy1-ap0`（2.4G，信道 5）；`interfaces[].config.encryption=psk2+ccmp`，`iwinfo` 里同时有结构化 encryption 对象。
5. `luci.vantage.wired` 的 hosts 里确实混着 `phy1-ap0` 的 WiFi 客户端（10 条中 8 条是无线），必须按 port 前缀过滤。
6. `getDHCPLeases` 返回 `dhcp_leases`/`dhcp6_leases` 两组；`getHostHints` 以大写 MAC 为 key。
7. `system info` 的 `load` 当前为 `[0,0,0]`（设备空载），`memory.available` 有效，uptime 是秒。
8. WAN 是 `dhcp`（上游 192.168.1.x），WAN6 是 `dhcpv6`，`ipprefix` 有 PD，默认路由 nexthop 为 `fe80::1`。
